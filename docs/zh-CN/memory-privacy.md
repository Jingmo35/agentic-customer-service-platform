# 记忆隐私边界

> 中文译文｜[英文原文](../memory-privacy.md)｜基准提交：`d2523b0`。本文描述上游项目设计，不代表个人已完成的开发成果。

记忆不是保存用户所有话语的数据库。它是受治理的状态，具有明确的隐私策略、客户范围、保留行为和受约束的操作员视图投影（operator projection）。

## 分类

每条候选记忆在持久化之前，都要确定：

- 敏感级别：`PUBLIC`、`INTERNAL`、`SENSITIVE` 或 `RESTRICTED`；
- 保留策略：标准、短期或不存储；
- 存储资格：允许、脱敏或拒绝；
- 脱敏状态。

分类器检测的类型化类别包括邮箱、电话号码、支付标识、IBAN、信用卡号、API 令牌、密码、秘密、国家身份标识和医疗健康术语。检测元数据只包含类别名称。检测到的具体值绝不会输出到日志或指标中。

## 写入时保护

记忆写入边界为：

```text
candidate → typed DLP classifier → allow | redact | reject
```

普通客户偏好仍属于内部受治理状态。邮箱和电话号码在存储前脱敏，且使用较短的保留期。支付标识、凭据、国家身份标识、医疗敏感内容及类似受限材料会被拒绝，永不持久化。原有针对指令性内容的保护仍然有效。

## 检索时保护

检索根据以下条件过滤：

- 服务端解析出的客户范围；
- 已认证主体的类型和角色；
- 记录的敏感级别。

客户主体只能检索自己范围内的记忆。客服操作员必须具备客服角色。即使数据库存在旧记录或手工创建的记录，受限记录也会被阻止读取。记忆服务不能授予授权、覆盖策略、代替确认或创建执行权限（execution authority）。

## 保留期

标准保留期沿用记忆类型现有的 TTL 策略。已脱敏的敏感记忆使用短期上下文 TTL。`no_store` 候选记忆在持久化前被拒绝。过期记录在检索时被过滤，同时仍受相同范围和敏感性检查约束。

数据库只在已有受治理记忆记录旁存储受约束的隐私元数据。模式变更通过 Alembic 迁移表示；迁移期间，历史记录会获得保守的默认值，即内部／标准保留期／无需脱敏。

## 可观测性

受约束的指标 `memory_dlp_allowed`、`memory_dlp_redacted`、`memory_dlp_rejected` 和 `memory_sensitive_retrieval_blocked` 只暴露策略结果，以及不包含具体类别的级别／原因。它们不包含记忆文本、检测到的值、客户标识符、个人身份信息（PII）、秘密、提示词或提供者数据。

记忆只用于丰富上下文。它不能授权操作、绕过策略或授予执行权限。
